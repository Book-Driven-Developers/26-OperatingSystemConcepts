# 대용량 저장장치 구조 정리 - HDD/NVM, 디스크 스케줄링 & RAID

## HDD (Hard Disk Drive)

물리적 구조

- Platter(플래터): 자성 물질로 코팅된 원판. 데이터가 실제로 기록되는 곳이다.
- Track(트랙): 플래터 표면의 동심원.
- Sector(섹터): 트랙을 잘게 나눈 조각으로 전송의 최소 단위이다. (전통적으로 512Byte, 최근에는 4KB)
- Cylinder(실린더): 여러 플래터에서 같은 위치에 있는 트랙들의 집합.
- Arm & Head: 암이 헤드를 원하는 트랙 위로 이동시키고, 헤드가 데이터를 읽고 쓴다.

Q. 디스크 접근 시간은 어떻게 구성될까?

A. Seek Time + Rotational Latency + Transfer Time

- Seek Time(탐색 시간): 헤드를 원하는 실린더까지 이동시키는 시간. 기계적 이동이므로 가장 비용이 크다.
- Rotational Latency(회전 지연): 원하는 섹터가 헤드 아래로 회전해 올 때까지 기다리는 시간.
- Transfer Time(전송 시간): 실제 데이터가 전송되는 시간.

디스크 성능 개선의 핵심은 결국 기계적으로 움직이는 Seek Time을 줄이는 것이고, 이것이 디스크 스케줄링의 목적이 된다.

## NVM (Nonvolatile Memory) - SSD & Flash

특징

- 기계적으로 움직이는 부품이 없다. -> Seek Time, Rotational Latency가 없다.
- HDD보다 빠르고 전력 소모가 적다. 대표적으로 NAND Flash 기반의 SSD가 있다.

NAND Flash의 제약사항

- 읽기/쓰기는 Page 단위, 삭제는 Block 단위(여러 페이지의 묶음)로만 가능하다.
- 덮어쓰기(overwrite)가 불가능하다. 
  - 수정하려면 다른 빈 페이지에 새로 쓰고 기존 페이지는 무효(invalid) 처리한다.
- 각 블록은 쓰기/삭제 횟수에 수명 제한이 있다.

Q. 덮어쓰기가 안 되면 무효 페이지가 쌓일 텐데 어떻게 처리할까?

A. Garbage Collection(GC)을 수행한다.

- 유효한 페이지만 다른 블록으로 복사한 뒤, 무효 페이지만 남은 블록을 통째로 삭제해서 빈 블록으로 만든다.
- GC용 작업 공간을 위해 실제 용량보다 여유 공간을 더 두는데, 이를 과잉공급(Over-Provisioning)이라 한다.

관리 기법

- 마모 평준화(Wear Leveling): 특정 블록만 반복적으로 지워지면 그 블록만 먼저 수명이 다하므로, 모든 블록에 쓰기/삭제가 고르게 분산되도록 컨트롤러가 관리한다.
- FTL(플래시 변환 계층, Flash Translation Layer): 덮어쓰기가 안 되서 데이터의 물리적 위치가 계속 바뀌므로, 논리 블록 주소가 현재 어느 물리 페이지에 있는지 매핑 테이블로 관리한다. Paging의 Page Table과 유사한 개념이다.

### 주소 매핑

- 저장장치는 Logical Block의 1차원 배열로 추상화되어 다뤄진다.
- 논리 블록 번호가 HDD에서는 (실린더, 트랙, 섹터)로, NVM에서는 (칩, 블록, 페이지)로 변환된다. 
- 파일시스템은 논리 블록 번호만 다루고 물리 위치 변환은 장치가 알아서 처리한다.

## HDD Scheduling (디스크 스케줄링)

디스크 I/O 요청 큐의 처리 순서를 바꿔서 Seek Time을 최소화하는 것이 목적이다. 
Seek Time은 헤드 이동 거리에 대략 비례하므로, 헤드 이동 거리를 줄이는 문제가 된다.

### 1) FCFS

- 들어온 순서대로 처리하는 방식.
- 공평하지만 헤드가 디스크 양 끝을 오가며 크게 움직일 수 있어 비효율적이다.

### 2) SCAN (엘리베이터 알고리즘)

- 헤드가 한쪽 끝에서 다른 쪽 끝으로 이동하면서 가는 길의 요청을 모두 처리하고, 끝에 도달하면 방향을 바꿔서 처리하는 방식.
- 엘리베이터가 한 방향의 요청을 모두 처리하며 이동하는 것과 동일하다.
- 위치에 따라 대기시간이 불공평하다. 
- 헤드가 방금 지나간 위치에 요청이 오면 끝까지 갔다가 돌아올 때까지 기다려야 한다. 즉 가운데 실린더가 양 끝보다 평균 대기시간이 짧다.

### 3) C-SCAN

- 끝에 도달하면 요청을 처리하지 않고 곧바로 처음 위치로 되돌아온 뒤 같은 방향으로만 처리한다.
- 실린더를 원형 리스트처럼 취급하여 모든 위치에서 대기시간이 균등해진다.

### NVM Scheduling

- NVM은 헤드 이동이 없으므로 SCAN 계열이 의미가 없다.
- 단순한 FCFS를 기본으로 하되, 인접한 요청들을 병합(merging)해서 요청 횟수를 줄이는 최적화를 한다.

## Storage Device Management

부트 블록 - Boot Block

- 전원을 켜면 ROM의 작은 Bootstrap Loader가 먼저 실행되고, 이것이 디스크의 Boot Block에 저장된 전체 부트스트랩 프로그램을 메모리에 올려 OS 커널을 로드한다.
- ROM에는 수정이 어려우니 최소한의 코드만 두고, 바뀔 수 있는 전체 부트 코드는 디스크에 두는 구조이다.

손상된 블록 - Bad Block 처리

- 사용 중 물리적으로 손상된 섹터를 Bad Block이라 한다.
- 섹터 예비(Sector Sparing): 컨트롤러가 예비 섹터를 확보해두고, bad block이 발견되면 해당 논리 블록을 예비 섹터로 매핑해준다.

스왑 공간 관리 - Swap-Space Management

- 메모리가 부족할 때 페이지를 내려놓는 디스크 공간이 Swap Space이다.
- 파일시스템 내 파일로 만들 수도 있지만, 파일시스템 오버헤드를 피하기 위해 별도의 Raw 파티션에 속도 최적화된 전용 관리자로 관리한다.
- Swap 데이터는 재부팅하면 사라지므로 단편화가 생겨도 문제되지 않는다.

## RAID (Redundant Arrays of Independent Disks)

여러 개의 디스크를 묶어서 1) 신뢰성과 2) 성능(병렬성)을 개선하는 기술이다.

디스크 N개를 묶은 만큼 N개 중 하나라도 고장 날 확률은 N배 커진다. 하지만 중복(Redundancy)을 두면 하나가 고장 나도 데이터를 잃지 않으므로, 데이터 유실 관점의 신뢰성은 오히려 올라간다. RAID로 고장을 막을순 없지만 고장이 나도 버틸수 있게 만든다.

핵심 기법 2가지

- 미러링(Mirroring): 동일한 데이터를 여러 디스크에 복제. 신뢰성은 확실하지만 용량이 절반이 된다.
- 데이터 스트라이핑 (Striping): 데이터를 여러 디스크에 블록 단위로 분산 저장. 여러 드라이브를 동시에 읽으므로 처리량이 올라간다.

RAID의 한계

- RAID는 디스크의 물리적 고장으로부터는 보호하지만, 파일시스템 버그나 사용자의 실수(파일 삭제) 같은 논리적 오류로부터는 보호하지 못한다. 
- 잘못된 데이터를 쓰면 그 잘못된 데이터가 완벽하게 미러링될 뿐이다. 따라서 RAID는 백업의 대체재가 아니다.
